# Evolution Tracking 后端设计

**版本:** 1.0  

---

## 概述

演化追踪帮助用户发现自己想法的变化。

**两个层次**：
1. **演化检测**：保存时提示"你之前记过类似的"
2. **Trace 管理**：将相关内容聚合成演化轨迹

---

## 演化检测

**触发**：每次新 Capture 保存后

**流程**：
```
新 Capture Embedding
    ↓
向量搜索（top 10，相似度 > 0.75）
    ↓
过滤：排除自身，排除 1 小时内
    ↓
有结果？→ 返回 EvolutionHint
```

**相似度阈值**：
- 0.65 宽松（可能有噪音）
- 0.75 平衡（推荐）
- 0.85 严格（可能漏掉）

> 注：演化检测提示使用较高阈值（0.75）以减少噪音；Trace 聚类使用较低阈值（0.70）以确保相关内容不被遗漏。

---

## Trace 管理

### 生成条件
- 同话题（相似度 > 0.7）
- 至少 3 条 Capture

### 生成流程
```
新 Capture 保存
    ↓
获取相关 Captures（相似度 > 0.7）
    ↓
检查是否属于现有 Trace
    ↓
是 → 添加到 Trace，更新 position
否 → 相关 ≥ 3 条？→ 创建新 Trace，AI 生成标题
```

### 标题生成 Prompt
```
以下是用户在不同时间记录的几条相关想法：
{captures_content}
请生成一个简短标题（不超过 10 字），概括核心主题。
```

---

## Related 内容计算

用于详情 Panel 显示"相关内容"。

**流程**：
1. 获取 Capture 的 Embedding
2. 向量搜索 top 10
3. 排除自身，排除同 Trace 中的
4. 返回 top 5

---

## Canvas 布局算法

将 Tag 按语义位置布局。

**流程**：
1. 获取所有 Tags
2. 计算每个 Tag 的"中心 Embedding"（其 Captures 平均值）
3. 降维到 2D（UMAP，n_neighbors=5-15）
4. 归一化到 [0, 100]

**缓存策略**：
- 缓存布局结果
- 新 Capture 或 Tag 变化时失效
- 用户访问 Canvas 时重新计算

---

## 数据一致性

**Capture 删除时**：
- 从 Traces 中移除
- Trace 中 < 3 条 → 删除 Trace
- 重新计算 position
- 清除 Canvas 缓存

**Tag 变化时**：
- 重新计算主 Tag
- 清除 Canvas 缓存

## 性能指标

| 操作 | 目标耗时 |
|------|----------|
| 演化检测 | < 500ms |
| Trace 检查 | < 200ms |
| Related 计算 | < 500ms |
| Canvas 布局 | 1-5s（可缓存） |
| 标题生成 | 1-2s（异步） |
