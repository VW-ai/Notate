# Notate 产品文档

**版本:** 2.0  
**日期:** 2025-01-20  
**状态:** MVP 定义

## 一、产品定位

### 1.1 一句话描述

Notate 是一个**轻量级的个人知识 Layer**，通过快捷键随时捕捉想法，用 AI 自动整理，让你的信息可以被复用——并帮你看到自己的想法如何演变。

### 1.2 核心价值主张

> "你的想法终于有地方去了，而且能被复用。"

**差异化价值层级：**

| Level | 价值 | 用户感受 |
|-------|------|----------|
| L1 | 捕捉 | "我记下来了" |
| L2 | 检索 | "我能找到" |
| L3 | Surface | "I didn't know I knew that" |
| **L4** | **演化追踪** | **"I didn't know I changed"** |

L4 是真正让用户觉得"这个工具理解我"的层级。

### 1.3 与竞品的本质区别

| 维度 | Task-completion 工具 | **Notate** |
|------|---------------------|------------|
| 价值主张 | "帮你完成任务" | "帮你整理和使用你的信息" |
| Context 的角色 | 手段（执行任务的素材） | **目的**（Context 本身就是价值） |
| End Goal | 任务完成了 | 你的知识库变得更好、更可用 |
| 策略 | 宽（什么都想做） | **窄但做得好** |

### 1.4 目标用户

- **B2C 个人用户**（不是 B2B）
- 有大量碎片化想法和信息需要整理的知识工作者
- 希望自己的 context 能够被复用，而不是每次都从零开始

## 二、产品架构

### 2.1 产品形态

```
┌─────────────────────────────────────────────────────────────────┐
│                        Notate 架构                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   用户 80% 的时间                    用户 20% 的时间              │
│                                                                  │
│   ┌─────────────────┐               ┌─────────────────┐         │
│   │    Overlay      │               │      App        │         │
│   │  (快捷键唤起)    │               │   (主界面)      │         │
│   │                 │               │                 │         │
│   │  • Quick Capture│               │  • Home         │         │
│   │  • Msg Refine   │               │  • Library      │         │
│   │  • 截屏 Context │               │  • Habits       │         │
│   │  • 演化检测提示  │               │                 │         │
│   └─────────────────┘               └─────────────────┘         │
│                                                                  │
│                         ↓  ↑                                     │
│              ┌──────────────────────────┐                       │
│              │      Knowledge Base       │                       │
│              │    (渐进式构建的知识库)    │                       │
│              │    + 演化追踪 (Traces)    │                       │
│              └──────────────────────────┘                       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 核心理念

1. **Overlay 优先**：用户大部分时间通过快捷键交互，不需要打开完整 App
2. **渐进式知识库**：用户从随手记想法开始，逐渐积累成完整的个人知识库
3. **整理 > 执行**：我们的价值在于帮用户整理信息，而不是替用户完成任务
4. **演化可见**：帮用户看到自己的想法如何随时间变化

## 三、核心功能

### 3.1 Quick Capture（快速捕捉）

**入口**：全局快捷键（如 `⌘ + Shift + Space`）

**核心交互**：
```
用户按快捷键 → Overlay 出现 → 输入想法 → Enter → 消失
```

**设计原则**：
- 零摩擦：从想到记录 < 3 秒
- 不需要分类：先 dump 进来，AI 后续整理
- 即时消失：记完就走，不打断心流

**支持的输入类型**：
- 💭 Thought（想法/随记）
- 🔗 Link（链接）
- 📄 File（文件）
- 📷 Screenshot（截屏获取 Context）

### 3.2 演化追踪（Evolution Tracking）

**核心洞察**（来自认知科学研究）：

> 人对自己观点变化的感知出奇地差。改变了想法，但不知道自己改变了。
> — Wolfe & Williams (2018)

**三层实现策略**：

| 层级 | 完成度 | 内容 |
|------|--------|------|
| 被动记录 | 100% | 完整保留时间戳、内容、类型、AI标签、关联 |
| 主动检测 | 70% | 捕捉时检测"同话题 + 内容不同"，提示用户 |
| 主动呈现 | — | MVP 暂不做（原计划的周报） |

**捕捉时检测流程**：

```
用户输入 → 保存成功 → 检测到"同话题、内容不同"
                              ↓
                    底部提示"💡 你 3 天前也记过类似的"
                              │
         ┌────────────────────┼────────────────────┐
         ↓                    ↓                    ↓
       忽略               点击提示              自动消失
         │                    │                 (几秒后)
         ↓                    ↓                    │
     提示消失          展开旧 capture 摘要          │
                              │                    │
                       ┌──────┴──────┐             │
                       ↓             ↓             │
                     关闭        跳转详情           │
                              └────────────────────┘
                                       ↓
                            后台自动建立"相关"关联
```

**配置选项**：默认先存后提示，用户可配置为静默标记

### 3.3 Knowledge Base（知识库）

**核心概念**：用户的所有 captures 汇聚成一个可搜索、可组织的个人知识库。

**AI 自动处理**：
- 自动打标签
- 提取关键信息
- 关联相关内容
- 生成摘要
- **聚类形成 Trace（演化轨迹）**

### 3.4 Library 视图

**四种视图回答不同问题**：

| 视图 | 回答的问题 |
|------|-----------|
| Timeline | "我最近记了什么" |
| Canvas | "我的知识分布在哪些领域" |
| Traces | "我的想法怎么变的" |
| Types | "我有哪些类型的内容" |

#### View 1: Timeline（时间线 - 默认）

按时间顺序展示所有 captures，适合回顾"今天/这周我记了什么"。

#### View 2: Canvas（知识地图）

- 每个 Tag 是一个区块
- 区块内是属于该 Tag 的 captures（卡片形式）
- 区块大小根据 capture 数量自适应
- 无连线，靠空间位置表达归属
- 整体可缩放、可拖拽浏览

**多 Tag 处理**：主 Tag 归属，每个 capture 只出现在一个区块

#### View 3: Traces（演化轨迹）

- 每个 Trace 是一条横向时间线
- 纵向排列多个 Trace（卡片墙形式）
- 默认紧凑卡片，点击展开详情

**Trace 定义**：
- AI 自动聚类同话题的 captures
- 生成条件：同话题 + 至少 3 条 capture
- 标题：AI 生成，用户可 inline 编辑
- MVP 不支持手动合并/拆分

#### View 4: Types（按类型）

- 用户输入类型：Thoughts / Links / Files
- AI 识别的实体：People / Companies / Projects

### 3.5 详情 Panel

点击任意卡片打开详情 Panel，包含：

1. **内容区**：完整内容、时间、标签
2. **Related 区**：语义相关的其他 captures
3. **Trace 区**（如果有）：
   - Trace 标题
   - 当前位置（第 X/Y 个）
   - 简化版时间线
   - 跳转完整 Trace 入口

**无 Trace 时**：显示空状态 + 引导文案（"当你有更多相关想法时，会自动形成轨迹"）

### 3.6 Habits（习惯）

**核心理念**：Habit 是**整理规则**，不是**任务执行**。用户用自然语言定义规则，AI 理解并执行。

**触发时机**：保存时推荐选择，用户有控制感

```
用户输入 YouTube 链接
         ↓
识别类型：YouTube 链接
         ↓
推荐匹配的 Habits：
  → Summarize Video（提取字幕，生成要点摘要）
  → Save to Research（保存到 #research）
  → Quick Save（只保存链接）
         ↓
用户选择一个执行
```

**创建入口**：
- Habits 页面 [+ New Habit]
- Overlay 输入 `/habit`
- 保存时推荐"要为这类内容创建 Habit 吗？"

**创建交互**：文本输入 → AI 解析展示理解 → 用户确认

**默认 Habits**（预装启用）：
- 链接 → 自动提取标题/摘要
- 图片 → OCR + 存储
- PDF → 索引内容

### 3.7 Message Refinement（消息优化）

**场景**：用户在写邮件/消息时，需要根据上下文润色表达。

**Context 获取**：截屏或粘贴

**流程**：
1. 获取 Context（截屏或粘贴）
2. 输入想要表达的内容
3. 选择 Style（可选）：Professional / Polite / Shorter / Longer
4. AI 生成优化后的消息 → 自动复制到剪贴板
5. 用户 Cmd+V 粘贴使用

## 四、AI 的角色

### 4.1 三个角色

**角色 1: Organizer（整理者）**
- 自动打标签
- 提取关键信息
- 识别关联
- 聚类形成 Trace

**角色 2: Habit Executor（习惯执行者）**
- 理解用户的自然语言规则
- 将规则转化为可执行的流程
- 在执行时做判断

**角色 3: Surface Agent（浮现者）**
- 检测新 capture 与历史的关联/矛盾
- 在捕捉时提示"你之前想过这个"
- 在详情里展示相关内容

### 4.2 AI 不做什么

- ❌ 不做通用任务执行
- ❌ 不做复杂的多步骤自动化
- ❌ 不主动打扰用户（除了捕捉时的轻量提示）

## 七、成功指标

### 7.1 核心指标

| 指标 | 目标 | 说明 |
|------|------|------|
| Daily Captures | 10+ / 用户 | 用户是否养成了随手记的习惯 |
| Knowledge Reuse Rate | 30%+ | 多少 captures 被后续复用 |
| Trace Engagement | 50%+ | 多少用户查看过 Traces 视图 |
| Habit Adoption | 3+ / 用户 | 用户是否在定义自己的习惯 |

### 7.2 North Star Metric

**Knowledge Reuse Rate（知识复用率）**

> 用户过去记录的内容，有多少被后续搜索、引用、或者在 Habit 中被使用？

## 八、认知科学基础

产品设计基于以下认知科学研究：

1. **Retrospective Sensemaking**（Weick）：意义是回顾性构建的，不是捕获时产生的
2. **Memory Distortion**（Wolfe & Williams）：人改变观点后，对原始观点的记忆会被当前观点污染
3. **Hindsight Bias**（Roese & Vohs）：人会觉得"早就知道了"，需要外部记录对抗
4. **Schema + Spreading Activation**：网络结构优于层级，相关概念会相互激活
5. **Transactive Memory**：人记住"在哪找"而非内容本身，检索能力比存储更重要

这些研究支撑了演化追踪功能的必要性和设计方向。
